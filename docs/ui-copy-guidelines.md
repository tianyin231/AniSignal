# AniSignal 文字规范与前端减负指南

> 本规范用于统一 AniSignal 全站中文文案口径、术语映射与高密度界面的信息组织方式。新增页面、接入新平台或修改既有文案时，均以本文档与 `web/app/utils/lexicon.ts` 为准。

---

## 一、文案基调与写作原则

AniSignal 定位为「信号台（Signal Desk）」，文字风格定位于**克制、准确、无歧义的书面产品语**——既不泄露内部工程实现，也不使用轻浮口语。

| 维度 | 避免：工程黑话 | 避免：过度口语 | 标准：克制书面产品语 |
| :--- | :--- | :--- | :--- |
| 单页内容追踪 | `page_watch` / `DOM diff` | 盯页面改动 | **`单页变更`** |
| 列表页新增追踪 | `list_watch` | 盯网站更新 | **`列表更新`** |
| 选择器输入项 | `内容区域选择器（CSS/XPath）` | 只盯页面某块区域 | **`内容区域`** |
| 官方原文变更 | `官方公告 revision` | 抓暗改 | **`官方原文修订`** |
| 准入策略与词表 | `tier=general` / `co_terms` | 标题里必须带着这几个字 | **`条件筛选`** / **`标题必含词`** |

### 四条基本约束

1. **词性对齐**
   - 导航、页签、类型、状态：使用对仗的 **2–4 字名词短语**（如 `单页变更` / `列表更新`、`全部收录` / `条件筛选`、`正常` / `异常` / `已停用`）。
   - 按钮、菜单项、动作：使用 **2–4 字动宾短语**（如 `新建监控`、`测试解析`、`保存更改`、`立即采集`）；区分可逆与永久操作（`移除` 解除关联，`删除` 永久清除）。
2. **名词与说明分层**
   - 不将解释塞进名词本身；仅在**创建或选择决策点**为选项配一行 ≤14 字的副标说明差异，列表、表格与徽章中只展示标准短名。
   - 延续项目既有约定：**禁止无意义的灰色解释性填充小字**，状态与结构优先用视觉层级表达。
3. **标点、空格与反馈语气**
   - 单行标签、按钮、徽章、表头、单句短提示**不加句号**；两句及以上的完整说明段使用句号。
   - 中文与英文字母、阿拉伯数字之间统一保留**半角空格**（`B 站`、`RSS 订阅`、`已启用 3 项`、`15 分钟`）。
   - 禁用感叹号 `！`；错误与禁用提示采用「**结果前置 + 原因或下一步**」。
4. **单一真相源**
   - 所有平台名、监控类型名、采集目标类型、内容形态与网页解析模式文案统一由 [`web/app/utils/lexicon.ts`](../web/app/utils/lexicon.ts) 导出，不在页面组件内重复维护映射字典。

## 二、全站标准术语表

| `bilibili` | **B 站** | `B` | 统一保留中英文空格，不再写作 `B站` |
| `rss` | **RSS 订阅** | `RSS` | 替代分散的 `新闻源`、`RSS 新闻源`、`RSS / Atom` |

| `list_watch` | **列表更新** | — | 决策副标：`监测目录或公告页新增文章链接` |

| 手动触发 AI 汇总邮件 | **AI 摘要邮件** | — | 按钮：`生成摘要邮件`，替代 `AI 精炼` |

| 共现词 (`co_terms`) | **标题必含词** | — | 直接表达过滤语义 |
| 后台 `/admin/ai` | **AI 配置** | — | 与 `AI 资讯` 明确区分，替代 `AI 层` |

### 2.2 网页监测进阶字段（默认收于「高级选项」）

| 字段 | 标签 | 占位符建议 |
| :--- | :--- | :--- |
| `selector` | **内容区域** | `留空自动提取正文，支持 CSS / XPath（如 main、#pricing）` |
| `exclude_selector` | **排除区域** | `如 .ads, footer, nav` |
| `link_pattern` | **链接规则** | `仅收录匹配路径，如 /blog/ 或 regex:...` |

## 三、高密度界面减负与布局约定

信息聚合工具天生具备高数据密度，优化重点是**信息分层、渐进披露与控制控件密度**，而非盲目放大空白：

1. **渐进披露（Progressive Disclosure）**
   - 表单主路径收敛在 2–3 个必填字段；选择器、排除规则、忽略内容、播放量门槛、采集间隔等低频参数归入默认折叠的 `高级选项`。
   - **条件渲染替代禁用占位**：某平台不适用的配置字段直接不渲染，不放置灰色禁用框占版面。
2. **情境化操作（Contextual Actions）**
   - 列表卡片与表格行最多常驻 **1–2 个高频操作**，其余编辑、公开范围、推送开关、启停、删除等统一归入溢出菜单（`⋯`）或侧滑抽屉。
3. **去边框堆叠**
   - 避免多层「卡片套边框套子盒」；优先使用字重阶梯、1px 细分割线（`border-line-soft`）与中性底色建立分组，品牌强调色仅用于激活态与唯一主操作。
4. **结构分区与表格列宽预算**
   - **管理后台导航**（`layouts/admin.vue`）：桌面端采用 **左侧轻量分组栏（200px）**，按工作流分为 4 组（`概览` / `信源与采集` / `内容与数据` / `用户与系统`），移动端折叠为分组抽屉。
   - **分区与信源管理**（`pages/admin/targets.vue`）：拆分为 `采集信源` / `站点分区` / `B 站登录态` 三个页签；新建与编辑信源使用右侧抽屉（Slide-over Drawer）；信源列表控制在 7 列以内。
   - **账号中心通知页**（`pages/account.vue`）：区隔为首屏直达的 `常用通知`（邮件通知、QQ 机器人）与次级区段 `开发者与进阶接入`（Webhook、个人 RSS、MCP 接入）。
   - **数据表格**：列数控制在 6–7 列以内，表头、状态与时间/数字列应用 `whitespace-nowrap` 与 `tabular-nums`，防止桌面端表头竖排折行。
5. **外观兼容性**
   - 所有新增与重构视图必须仅使用 `main.css` 定义的 `--sd-*` 语义色变量，并在浅色模式、暗黑模式与随机壁纸（`data-wallpaper` / `.wall-surface`）三种状态下核对可读性。
