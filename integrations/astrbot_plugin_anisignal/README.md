# AniSignal 情报助手

在 AstrBot 中订阅游戏与 AI 资讯，查询早报、商品进展、活动和兑换码，并向指定群聊或私聊发送通知。资讯由 AniSignal 服务采集，插件负责会话配置、查询与投递；人格和日常聊天模型在 AstrBot 中设置。

需要 AstrBot **4.28.2 或以上**、可访问的 AniSignal 服务，以及该服务签发的插件专用密钥。

## 快速接入

1. 在 AstrBot 的「插件管理 → 安装插件 → 从链接安装」中填写 `https://github.com/tianyin231/AniSignal`，点击安装。仓库根目录已提供插件入口、元数据、设置和依赖声明，AstrBot 会自动安装依赖。后续更新继续使用同一仓库。
2. 也可手动将本目录完整复制到 AstrBot 的 `data/plugins/astrbot_plugin_anisignal/`。保留 `main.py`、`configuration.py`、`notification_template.py`、`card.py`、`_conf_schema.json`、`metadata.yaml` 和 `requirements.txt`，安装依赖后在插件管理中加载或重载：

   ```bash
   # 在 AstrBot 项目目录执行
   python -m pip install -r data/plugins/astrbot_plugin_anisignal/requirements.txt
   ```

3. 打开 AniSignal 管理端 `/admin/bot`，在「AstrBot 接入」中创建独立接入密钥。密钥只显示一次，每个 AstrBot 实例单独创建一个。
4. 在 AstrBot 的 AniSignal 插件设置中填写：

   | 设置 | 填写方式 |
   | --- | --- |
   | AniSignal 服务地址 `base_url` | 服务根地址，例如 `http://anisignal.xyz`；插件会自动拼接 API 路径 |
   | 专用插件密钥 `tools_key` | 上一步生成的密钥；管理员 Token 不能用于此处 |
   | 卡片中文字体 `card_font_path` | 可留空；自定义时填写 AstrBot 运行环境内的字体文件路径 |

5. 在目标群聊或私聊发送 `/情报会话`，复制完整的会话标识（UMO）。如果平台要求 @ 机器人才能响应，先 @ 再发送命令。
6. 在插件设置的「会话订阅」中新增一项，填写名称和 UMO，打开「启用此会话的推送与查询」，选择频道、通知和工具后保存。
7. 等待约 30 秒同步，再发送 `/情报会话`、`/帮助` 和 `/早报` 检查接入。

AstrBot 所在容器或主机必须能访问填写的服务地址。插件约每 30 秒同步配置、每 15 秒领取待发送通知；AniSignal 的采集和调度服务也需正常运行。

## 订阅范围

每个群聊或私聊独立配置。**选了频道时按频道筛选；频道留空时使用订阅分区。** 关键词进一步限定关注内容，留空表示不额外限定关键词。

| 频道格式 | 含义 | 示例 |
| --- | --- | --- |
| `<分区>:official:<平台>` | 对应平台的官方内容，包括已接入的官方周边账号 | `wuwa:official:bilibili` |
| `<分区>:community:<平台>` | 对应平台的社区内容 | `wuwa:community:bilibili` |
| `<分区>:product` | 商品公告及已采纳的履约变化 | `wuwa:product` |
| `ai:news` | AI 资讯 | `ai:news` |

分区代码：`wuwa` 鸣潮、`blhx` 碧蓝航线、`hsr` 星穹铁道、`arknights` 明日方舟、`genshin` 原神、`endfield` 终末地；`ai` 为 AI 资讯。

平台代码：`bilibili`、`youtube`、`x`、`web`、`miyoushe`。设置页提供可选项，具体内容取决于服务端实际接入的来源；选择频道只改变订阅范围。

例如只关注鸣潮的 B 站官方消息和商品进展，可以选择 `wuwa:official:bilibili`、`wuwa:product`，关键词留空。

首次连接时，若插件的会话列表为空，会导入该接入在服务端已有的会话配置。之后在 **AstrBot 插件设置**中维护订阅；移除列表项会暂停对应会话并保留历史投递记录。

## 常用命令

`/帮助` 会按当前会话开放的功能显示可用项。

| 命令 | 用途与前提 |
| --- | --- |
| `/情报会话` | 查看注册状态、完整 UMO 和自己的管理标识 |
| `/早报` | 查询近 24 小时速报，需要 `digest` 工具 |
| `/资讯 关键词` | 查询近 7 日资讯，需要 `news` 工具；关键词可省略 |
| `/商品 关键词` | 查询商品资料、官方说明与履约证据，需要 `products` 工具 |
| `/展开 2` | 按刚才清单的第 1～3 条查看来源快照，需要开放 `digest` 或 `news` |
| `/情报订阅` | 查看当前会话的订阅设置 |
| `/我的提醒` | 查看自己的定时提醒，需要开启提醒 |
| `/聊点什么` | 用今日资讯发起话题，需要开启互动和 `digest` 工具 |
| `/情报挑战` | 根据今日资讯出三选一题，需要开启互动和 `digest` 工具 |
| `/帮助` | 查看本会话的功能与状态 |

开启相应工具后，还可以直接问「最近什么火」「最近有什么活动或维护」「有没有兑换码」，分别使用 `trending`、`calendar`、`codes` 工具。自然语言查询和操作需要会话模型支持工具调用。

展开沿用原清单的编号与资料快照。也支持「第 2 条展开」等说法；「压缩内容时显示展开入口」只控制提示是否出现，默认关闭，手动展开仍可使用。

## 通知与权限

| 设置 | 默认值与作用 |
| --- | --- |
| 每日早报 | 开启，时间为北京时间 `08:00` |
| 重要动态 | 默认关闭，开启后接收订阅范围内的动态 |
| 活动收尾提醒 | 默认开启，但需同时开启重要动态；默认 `20:00` 汇总未来 24 小时的截止和维护，每天最多一条 |
| 免打扰 | 默认 `23:00`～次日 `08:00`；开始与结束相同表示关闭 |
| 关键动态穿透免打扰 | 默认关闭 |
| 普通动态合并窗口 | 默认 `0` 分钟，可按需合并消息 |
| 自动消息频率 | 默认每小时最多 `2` 条、最小间隔 `20` 分钟；小时上限为 `0` 表示不限 |
| 早报发送方式 | `compact` 合并发送，`split` 总览与重点分条发送 |
| 单次最多附图 | 默认 `1` 张，最多 `9` 张；早报卡片占一张 |

免打扰与自动消息频率适用于自动早报、动态及活动提醒。用户创建的定时提醒单独调度，发送到创建提醒的会话。

聊天修改订阅默认关闭。启用后，可说「只关注鸣潮」「把早报改到九点」「关闭重要动态」等；**群内只有 `manager_ids` 中的用户可以修改全群订阅**，管理标识从 `/情报会话` 获取。修改成功会保存回插件设置。

定时提醒默认关闭。启用后，可说「明天上午九点提醒我付尾款」或「取消我的第 3 号提醒」。用户只能管理自己的提醒，群内提醒会在本群公开发送；可设置 30 秒后至 90 天内的时间，按分钟调度。

## 回复方式与人格

「主动查询回复方式」控制用户发命令时的回复：

- `bot`：默认，使用 AstrBot 当前会话的人格、模型和输出流程。
- `text`：直接返回资料文字。
- `card`：早报使用原始情报卡，其他查询返回资料文字。

自动通知单独设置：

- 「主动通知的引导语」默认跟随当前人格；选择 `original` 可直接发送资料。
- 「主动通知的展示格式」默认早报卡片，其余通知使用文字。
- 「主动通知模型」留空跟随当前会话模型，仅影响通知引导语。
- 「情报排版与详略补充」用于段落、篇幅和语言等偏好，当前会话人格仍优先。

通知模型生成失败时继续发送资料正文，原因记录在投递记录中。早报卡片需要 Pillow 与可用的中文字体，生成失败会退回文字。

## 自定义通知模板

模板在每个会话的「回复与通知呈现」中设置，按字面替换字段，不执行代码。

默认「通知消息模板」为：

```text
{intro}

{body}
```

| 字段 | 内容 |
| --- | --- |
| `{intro}` | 当前人格生成的引导语；模板中省略它就不调用通知模型 |
| `{body}` | 服务端生成的通知正文 |
| `{items}` | 按「每条内容模板」逐条组装资料 |
| `{title}`、`{summary}` | 标题与摘要 |
| `{content}`、`{original}` | 已保存的来源正文快照 |
| `{time}` | 来源发布时间，显示为北京时间 |
| `{source}`、`{url}` | 来源名称与原文链接 |
| `{images}` | 在该位置发送实际图片 |
| `{image_urls}` | 图片链接文字 |
| `{schedule}` | 活动名称及截止时间，或维护开始时间 |
| `{details_hint}` | 开启展开提示且资料被压缩时的展开入口 |
| `{index}` | 条目序号，通常用于「每条内容模板」 |

使用 `{items}`、`{title}`、`{images}` 等拆分字段后，通知严格按模板组装，图片由 `{images}` 控制。默认 `{intro}` + `{body}` 模板则继续使用前面的卡片或文字设置。

例如按条列出来源并附图，可将「通知消息模板」改为：

```text
{intro}

{items}

{details_hint}
```

「每条内容模板」填写：

```text
{index}. {title}
{summary}
发布时间：{time}
来源：{source}
{url}
{images}
```

将 `{summary}` 改为 `{content}` 可展示来源正文快照。图片仍遵守整条通知的附图上限，同一图片只发送一次。`{time}` 是发布时间，活动截止或维护开始时间使用 `{schedule}`。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 会话显示未注册或已暂停 | 核对完整 UMO、会话启用开关，保存后等待同步；查看日志中的配置同步错误 |
| 提示未启用工具或 HTTP 403 | 检查专用密钥、接入启用状态，以及该会话的允许工具 |
| 查询正常但没有自动推送 | 检查通知开关、所选频道是否有新内容、免打扰、频率限制，以及 AniSignal 的调度和投递记录 |
| 卡片未生成或没有中文 | 在 AstrBot 运行环境安装 Pillow 和中文字体，或设置 `card_font_path`；原文模式可直接使用文字 |
| 多条内容只有一张附图 | 检查「单次最多附图」，默认只允许一张，早报卡片也计入上限 |
| 模板没有显示正文或图片 | 检查是否保留了需要的 `{body}`、`{items}`、`{images}` 字段 |
| 自然语言操作没有生效 | 检查模型工具调用、聊天管理或提醒开关，以及群管理标识；以工具返回成功为准 |
| 投递记录为 `unknown` | 发送结果无法确认，先核对群聊是否已经收到，再决定是否手动重试 |

插件配置入口为 AstrBot 的 AniSignal 插件设置，接入状态与投递记录在 AniSignal 管理端 `/admin/bot` 查看。查询结果为空表示当前订阅范围内没有找到相应资料。
