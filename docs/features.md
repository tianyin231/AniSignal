# 功能与使用指南

[返回首页](../README.md) · [部署指南](deployment.md)

使用路径是：**划定范围 → 采集与降噪 → 阅读与追溯 → 按关注送达**。站点上的作品、账号和商品来自运行时配置；平台与分区的扩展以已实现的适配器和注册项为界。

## 先区分三种关注方式

| 方式 | 谁来配置 | 对什么生效 | 是否新增采集任务 |
| --- | --- | --- | --- |
| **站点采集目标** | 管理员 | 已支持平台的关键词、账号或公告来源；进入主内容库和事件处理链路 | 是 |
| **关键词关注** | 登录用户 | 站内已采集的内容；形成个人关注流，并用于关键词通知 | 否 |
| **定制监控** | 登录用户 | 独立的 B 站 UID 动态或关键词视频搜索；可设公开或私有 | 是，结果独立存储 |

普通关注流目前按**标题关键词**匹配，不是全网搜索。通知有独立的候选筛选规则，不能把关注流条数直接理解为邮件条数。当前代码分别限制每个账号最多 10 个关注词、10 个定制监控。

定制监控条目不会进入主内容库、事件聚合或商品履约计算。公开监控可在 `/custom` 浏览；“私有”表示不公开展示，不代表端到端加密或对部署管理员不可见。

实现参考：[账号 API](../server/app/api/account.py)、[定制监控服务](../server/app/services/custom_feeds.py)。

## 浏览、搜索与追溯

| 页面 | 用途 |
| --- | --- |
| `/` | 聚合首页；切换已注册分区，查看精选、事件与内容更新。 |
| `/official`、`/contents`、`/search` | 浏览官方动态、筛选内容或搜索站内已采集信息。 |
| `/contents/{id}` | 查看可用正文、媒体预览、来源链接和关联信息；预览完整度取决于源站数据。 |
| `/events`、`/events/{id}` | 查看归并事件、关键事实、证据与修订记录。 |
| `/ai` | 独立阅读 AI 快讯，按主题、报道／传闻和时间筛选，核对原始出处。 |
| `/products`、`/products/{slug}` | 查看商品档案、进展概览、时间线及信号证据。 |
| `/custom`、`/custom/{id}` | 浏览用户公开的独立监控与条目。 |
| `/sources`、`/stats` | 查看来源健康状态与站点数据统计，判断采集范围和运行情况。 |
| `/account` | 管理个人资料、关注词、定制监控、邮件设置与投递记录。 |

内容预览与事件结论都应保留原始来源作为核对入口。“没有找到”只代表当前已接入来源和查询范围内没有匹配结果，不代表外部没有更新。

## 管理员如何决定采集内容

在 `/admin/targets` 新建或调整采集目标，选择平台、分区、目标类型和值，再设置采集周期、启停状态和筛选参数。手动触发后，先检查采集结果及来源健康，再检查内容分类与事件关联。

当前采集编排注册了以下来源适配器：

| 来源 | 实现范围 |
| --- | --- |
| Bilibili | B 站采集器，依赖 `bili` CLI；具体目标类型由采集器实现。个人定制监控支持 UID 动态和关键词视频搜索。 |
| 米游社 | 米游社专用采集与解析适配器，不代表任意社区网站。 |
| 库洛官网 | 国服与国际服公告适配器，不是任意官网抓取器。 |
| YouTube | 频道上传列表；配置 API Key 后优先使用 Data API v3，未配置或失败时回退 RSS。 |
| X | 低频读取公开账号动态，目前仅支持账号监控；登录限制、访问拒绝与无法解析的页面计入来源健康。 |

平台注册见[采集编排](../server/app/services/collect.py)。分区注册见[communities.py](../server/app/communities.py)；新增分区还需同步相应枚举、前端配置及必要的历史数据迁移，不能只改展示名称。

### 筛选、归并和审核不是同一层

**采集筛选**决定哪些结果进入主链路。泛关键词可设置标题共现词和热度门槛；核心关键词豁免共现词条件，但设置了播放量下限时仍会检查。过严的规则可能漏掉相关内容，应结合结果复核。

**内容处理**负责解析、分类和版本记录；配置模型服务后，可追加 AI 筛选、摘要与翻译。管理端支持内容审核与人工调整，AI 结果不构成来源事实的保证。

**事件归并**目前以规则为主：同分区内，符合分类、时间窗口及标题相似条件的官方内容可以归并；商品线索按监控词关联。不是所有采集条目都会成为事件，也不承诺跨语言语义归并。人工锁定的事件优先于自动处理。

实现参考：[事件引擎](../server/app/services/events.py)、[任务注册](../server/app/worker/settings.py)。

## AI 快讯

`/ai` 使用独立的资讯分区，按模型、产品与行业主题阅读内容，区分报道与传闻，保留标题、摘要、发布时间、原帖和引用链接。只有通过当前版本资讯审核且仍可见的内容进入公开快讯；筛选通过不等于事实已核实。

AI 分区使用新闻筛选语境，不套用游戏词典与商品履约规则。来源范围仍由管理员的采集目标决定，页面会展示已配置来源的采集状态。

## 商品进展：先看证据，再看状态

商品监控词用于关联主内容库中的线索。商品详情将**官方进展、消费者到货、质量反馈**分开呈现，并保留事件时间线和信号证据。

公开结论只统计已核验信号。待核验线索不参与公开状态计算；送测样品不计入普通消费者到货样本。这里追踪的是公开证据，不提供电商下单、订单查询或个人发货日期预测。

页面参考：[商品详情](../web/app/pages/products/[slug].vue)。

## 邮件、AI 与机器人

| 能力 | 当前方式 | 使用前提 |
| --- | --- | --- |
| 邮件早报 | 按北京时间每天 08:00 的调度发送全站早报，并记录投递结果 | SMTP 可用、邮箱验证、通知设置和调度服务正常 |
| 手动邮件 | 账号中心请求早报或 AI 关键词通知；按权限、配置与限频规则处理 | AI 关键词通知还需要启用关注词和模型服务 |
| 定制监控推送 | 独立监控发现新增内容后按限制发送邮件，不是每条内容实时推送 | 监控开启推送、账号符合条件、SMTP 可用 |
| AI 辅助 | 事件摘要、外语翻译、内容筛选与用量记录 | 配置兼容的模型接口、密钥和模型；可能产生外部服务费用 |
| AstrBot 集成 | 查询速报、资讯和商品进展，并通过配置的会话通道投递 | 单独部署机器人并配置桥接、会话及访问凭据 |

早报与定制监控邮件不要求所有条目先成为事件。投递记录用于查看实际处理状态；功能存在不代表当前试运行部署已经启用，也不保证外部邮件或消息平台最终送达。

实现参考：[通知服务](../server/app/services/notifications.py)、[定制推送](../server/app/services/custom_feeds.py)、[机器人服务](../server/app/services/bot.py)、[AstrBot 插件](../integrations/astrbot_plugin_anisignal/)。

## 管理与反馈

管理端提供采集目标、分类规则、内容、事件、商品、用户、定制监控、站点设置、AI 和机器人相关入口。管理员配置决定公共内容范围；个人关注与独立监控不应被描述为自动改变整个站点的采集策略。

反馈采集遗漏时，请提供平台、目标类型、相关公开链接和大致时间；反馈误归并或商品结论时，请同时提供事件／商品链接及原始证据。不要在 Issue 中上传管理员 Token、API 密钥、邮箱凭据或他人的订阅数据。
