# 功能与使用指南

[返回首页](../README.md) · [部署指南](deployment.md)

使用路径是：**划定范围 → 采集与降噪 → 阅读与追溯 → 按关注送达**。站点上的作品、账号和商品来自运行时配置；平台与分区的扩展以已实现的适配器和注册项为界。

## 先区分三种关注方式

| 方式 | 谁来配置 | 对什么生效 | 是否新增采集任务 |
| --- | --- | --- | --- |
| **站点采集目标** | 管理员 | 已支持平台的关键词、账号或公告来源；进入主内容库和事件处理链路 | 是 |
| **关键词关注** | 登录用户 | 站内已采集的内容；形成个人关注流，并用于关键词通知 | 否 |
| **定制监控** | 登录用户 | 独立的 B 站关键词视频搜索、B 站 UP 主动态、RSS / Atom 订阅源、自定义网页（单页变更 / 列表新增）、GitHub 版本发布、YouTube 频道（支持链接、@handle、UC 频道 ID）、Steam 游戏或小黑盒监控；可设公开或私有 | 是，结果独立存储 |

普通关注流目前按**标题关键词**匹配，不是全网搜索。通知有独立的候选筛选规则，不能把关注流条数直接理解为邮件条数。当前代码限制每个账号最多 10 个关注词；定制监控默认每个账号 3 个、最短 60 分钟采集一次，管理员可在后台「定制监控」页的策略里调整。X 账号目前只能由管理员作为站点采集目标添加。

定制监控条目不会进入主内容库、事件聚合或商品履约计算。公开监控可在 `/custom` 浏览；“私有”表示不公开展示，不代表端到端加密或对部署管理员不可见。

实现参考：[账号 API](../server/app/api/account.py)、[定制监控服务](../server/app/services/custom_feeds.py)。

## 浏览、搜索与追溯

| 页面 | 用途 |
| --- | --- |
| `/` | 聚合首页；切换已注册分区，查看精选、事件与内容更新。 |
| `/official`、`/contents`、`/search` | 浏览官方动态、筛选内容或搜索站内已采集信息。 |
| `/contents/{id}` | 查看可用正文、媒体预览、官方原文修订 Diff、来源链接和关联信息；预览完整度取决于源站数据。 |
| `/calendar` | 跨游戏活动月历、甘特图与倒计时视图，支持单条导出 `.ics` 及整分区 `webcal://` 实时订阅。 |
| `/events`、`/events/{id}` | 查看归并事件、关键事实、证据与修订记录。 |
| `/ai` | 独立阅读 AI 快讯，按主题、报道／传闻和时间筛选，查看日报/周报归档与来源健康，核对原始出处。 |
| `/reports`、`/reports/{id}` | 浏览公开分区与个人定制监控合集的周期报告（日报 / 周报）归档，支持上一期/下一期翻阅与按需触发生成。 |
| `/products`、`/products/{slug}` | 查看商品档案、进展概览、时间线及信号证据。 |
| `/steam` | 查看已接入 Steam 游戏的实时在线人数、好评率、评测趋势与官方公告。 |
| `/custom`、`/custom/{id}` | 浏览用户公开的独立监控与条目。 |
| `/sources`、`/stats`、`/project` | 查看来源健康状态、站点数据统计与开源更新记录，判断采集范围和运行情况。 |
| `/account` | 管理个人资料、关注词、定制监控、Webhook、周期报告订阅、个人专属 RSS、AI 助手 MCP 令牌与投递记录。 |

内容预览与事件结论都应保留原始来源作为核对入口。“没有找到”只代表当前已接入来源和查询范围内没有匹配结果，不代表外部没有更新。

## 管理员如何决定采集内容

在 `/admin/targets` 新建或调整采集目标，选择平台、分区、目标类型和值，再设置采集周期、启停状态和筛选参数。手动触发后，先检查采集结果及来源健康，再检查内容分类与事件关联。

当前采集编排注册了以下来源适配器：

| 来源 | 实现范围 |
| --- | --- |
| Bilibili | B 站采集器，依赖 `bili` CLI；支持官号动态、UP 主投稿与关键词搜索。个人定制监控支持 UP 主动态和关键词视频搜索。 |
| 米游社 | 米游社专用采集与解析适配器，不代表任意社区网站。 |
| 库洛官网 / 游戏官网 | 库洛国服与国际服公告、通用游戏官网公告适配器，不是任意官网抓取器。 |
| YouTube | 频道上传列表；配置 API Key 后优先使用 Data API v3，未配置或失败时回退免密钥 RSS。 |
| RSS / Atom | 标准 RSS / Atom 订阅采集与正文提取，支持 ETag / Last-Modified 缓存协商与逐跳 SSRF 校验，后台与用户定制监控均可用。 |
| X | 低频读取公开账号动态，目前仅支持管理员账号监控；登录限制、访问拒绝与无法解析的页面计入来源健康。 |
| 自定义网页（`web_page`） | 支持单页变更监控（`page_watch`，自动触发版本 Diff 与修订通知）与列表页新增发现（`list_watch`）；组合 `parsel`、`trafilatura`、`readability-lxml` 与 `html2text` 通用解析栈，支持可选 CSS / XPath 选择器、排除区域、忽略行与测试解析预览（含官方 RSS 自动探测与 SPA 提示），仅访问公开静态/SSR 网页并执行逐跳 SSRF 校验。 |
| GitHub | 公开开源信源适配器，默认纯匿名运行（可选环境变量 `ANISIGNAL_GITHUB_TOKEN` 提额）；支持版本发布（API + `ETag` 304 + 限流自动回退公开 Atom，后台与用户定制监控均可用）与趋势榜单（`daily` / `weekly` / `monthly`，按期归档日刊/周刊/月刊并自动跨期去重打标、匿名抓取 README 与生成 AI 中文解读）。 |
| Steam | 商店游戏官方新闻与公告采集，并周期记录游戏实时在线人数、好评率与评价数快照（在 `/steam` 展示趋势）；后台与用户定制监控均可用。 |
| 小黑盒 | 社区话题与公开分享内容采集，内置「小黑盒」主题流分区，也支持用户定制监控。 |

平台注册见[采集编排](../server/app/services/collect.py)与[解析注册](../server/app/services/ingest.py)。内置分区定义见[communities.py](../server/app/communities.py)，同时支持管理员在 `/admin/targets` 实时创建与启停自定义分区（无需改动代码）。

### 筛选、归并和审核不是同一层

**采集筛选**决定哪些结果进入主链路。泛关键词可设置标题共现词和热度门槛；核心关键词豁免共现词条件，但设置了播放量下限时仍会检查。过严的规则可能漏掉相关内容，应结合结果复核。

**内容处理**负责解析、分类和版本记录；配置模型服务后，可追加 AI 筛选、摘要与翻译。管理端支持内容审核与人工调整，AI 结果不构成来源事实的保证。

**游戏事件归并**以规则为主：同分区内，符合分类、时间窗口及标题相似条件的官方内容可以归并；商品线索按监控词关联。不是所有采集条目都会成为事件。AI 快讯使用下述独立编辑链路，人工锁定的事件优先于自动处理。

实现参考：[事件引擎](../server/app/services/events.py)、[任务注册](../server/app/worker/settings.py)。

## AI 快讯

`/ai` 使用独立的资讯分区，按模型、产品与行业主题阅读内容，区分报道与传闻，保留标题、摘要、发布时间、原帖和引用链接。只有通过当前版本资讯审核且仍可见的内容进入公开快讯；筛选通过不等于事实已核实。

AI 分区使用新闻筛选语境，不套用游戏词典与商品履约规则。来源范围仍由管理员的采集目标决定，页面会展示已配置来源的采集状态。

编辑机制参考 [AIHOT](https://github.com/KKKKhazix/AIHOT)，以 Python 接入现有数据模型与队列：同一次发生合并来源，直接后续保留为新进展，综合稿不用于合并独立事件。最新内容优先处理，未完成归组的已审核原文仍可阅读。

页面提供最新、热点与精选。热点统计近 48 小时的独立参与方，按 24 小时半衰期衰减；配置同一主体的 `owner_key` 可避免跨账号重复计数，至少两方才进入热点。精选需要两次独立评分达到来源门槛，默认一手来源 60、媒体 76；分数表示编辑价值，不代表事实认证。

日报按北京时间 07:50 截稿、08:00 成刊，已出刊内容固定，撤稿或修订会撤下受影响文案。邮件与机器人复用当期内容；首日或尚无当期日报时沿用原通道降级。管理端 AI 页可设置来源主体、门槛、模型和请求额度，查看回执；页面读取不会触发模型请求。

实现参考：[归组与评分](../server/app/services/news_editorial.py)、[热度与日报](../server/app/services/news_publication.py)、[模型调用回执](../server/app/services/editorial_calls.py)。

## 商品进展：先看证据，再看状态

商品页把同一份结论放在总览和侧栏：实物开箱（独立账号和日期，购买方式未写明不会写成自购到货）、质量反馈、官方说明。没有采集到的官方原文时，预售和发货文字标为登记信息。证据按时间列在商品页，不再另排一条事件时间线。

窗口结束的商品仍可打开，专属搜索会停。公开结论只统计已采纳信号。送测和购买方式未注明的开箱不计入自购样本。这里不提供电商下单、订单查询或个人发货日期预测。方向说明见 [商品监控循环](archive/2026-10-21-product-monitor-loop.md)。

页面参考：[商品详情](../web/app/pages/products/[slug].vue)。

## 通知、周期报告、Webhook、机器人与 MCP

| 能力 | 当前方式 | 使用前提 |
| --- | --- | --- |
| 邮件早报与即时提醒 | 按北京时间每天 08:00 发送全站早报，并对重点更新与官方原文修订触发即时提醒，全程记录投递结果 | SMTP 可用、邮箱验证、通知设置和调度服务正常 |
| 通用周期报告（`/reports`） | 覆盖公开分区（多订阅者复用当期报告，零重复模型调用）与用户定制监控合集；北京时间每天 08:30（日报）/ 每周一 08:30（周报）自动归档并经邮件或 Webhook 投递，也支持手动生成。配置 AI 时按主题聚类（链接严格回填库内条目），无 AI 或超额时自动降级为确定性分组清单 | 账号开启周期报告订阅（每人最多 5 条）；推送依赖 SMTP 或已配置的 Webhook |
| 7 种 Webhook 推送 | 支持飞书、钉钉、企业微信、Discord、Bark、ntfy 与通用 JSON（每人最多 3 个）；可选按关键词、全量重点、仅官方原文修订或仅周期报告触发，每次出站前实时校验 DNS 与私网 IP | 目标地址为公开 http(s) 地址；与邮件共用每日通知配额 |
| 公共与个人专属 RSS | 提供全站 / 分区 `/rss.xml`（支持 `?revised_only=true` 仅看官方修订）、AI 精选 `/api/ai-news/rss.xml`，以及账号中心签发的个人专属令牌过滤 RSS | 个人专属 RSS 需登录并在账号中心复制或重置令牌 |
| 定制监控推送 | 独立监控发现新增内容后按限制发送邮件，不是每条内容实时推送 | 监控开启推送、账号符合条件、SMTP 可用 |
| AI 辅助 | 事件摘要、外语翻译、主题流与开源项目中文解读、内容筛选、周期报告聚类与用量记录 | 配置兼容的模型接口、密钥和模型；可能产生外部服务费用 |
| QQ 机器人集成 | 提供 AstrBot 与 DeepSeek Harness（`dsh`）双插件，支持官方 QQ Bot 与 OneBot v11，查询速报、资讯、商品进展并推送图文早报卡片 | 单独部署机器人并配置实例地址与访问凭据 |
| 只读 MCP Server（`/mcp`） | 遵循 Streamable HTTP 的无状态只读接口，供 Claude Code、Cursor、Windsurf、Antigravity 等 AI 客户端调用跨语言检索、日历、兑换码、修订 Diff、周边、Steam 遥测与个人关注流 | 公开工具免登录即可接入；个人关注与偏好过滤需携带个人令牌 |

早报、周期报告与定制监控邮件不要求所有条目先成为事件。投递记录用于查看实际处理状态；功能存在不代表当前试运行部署已经启用，也不保证外部邮件或消息平台最终送达。

## 管理与反馈

管理端提供采集目标、分类规则、内容、事件、商品、用户、定制监控、站点设置、AI 和机器人相关入口。管理员配置决定公共内容范围；个人关注与独立监控不应被描述为自动改变整个站点的采集策略。

反馈采集遗漏时，请提供平台、目标类型、相关公开链接和大致时间；反馈误归并或商品结论时，请同时提供事件／商品链接及原始证据。不要在 Issue 中上传管理员 Token、API 密钥、邮箱凭据或他人的订阅数据。
